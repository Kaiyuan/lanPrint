Deploy the lanPrint bridge

A small Rust relay server that lets a host and a client establish a connection across the internet. Run it on any Linux or macOS machine, or in Docker.

Architecture Docker Docker Compose One-line install HTTPS / reverse proxy Configuration Connect clients Security API reference

How the bridge works

The host registers with the bridge using the server access code and receives a short share code. The host keeps an outbound WebSocket, so it works behind NAT without opening a port. A client that knows the share code asks the bridge for a session, then multiplexes HTTP-like requests over its own WebSocket. The host verifies all printer access codes locally.

1 · Host

Registers, gets a share code and maintains a relay WebSocket.

2 · Bridge

Matches share codes, authenticates server/host/client tokens and forwards frames.

3 · Client

Connects with the share code and uses the same API as on the LAN.

There is no inbound port on the host and no cloud account. The share code is the only routing secret a client needs, together with the printer access code.

Run with Docker

docker run -d --name lanprint-bridge \
  --restart unless-stopped \
  -p 52334:52334 \
  -e LANPRINT_BRIDGE_AUTH_CODE='replace-with-a-long-random-code' \
  -e LANPRINT_BRIDGE_PUBLIC_URL='https://bridge.example.com' \
  -v lanprint-data:/data \
  kaiyuan/lanprint-bridge:latest

The image is published for linux/amd64 and linux/arm64 on Docker Hub as kaiyuan/lanprint-bridge. The /data volume stores share-code mappings so hosts keep the same code after a restart.

Always put the bridge behind HTTPS before exposing it to the internet. Do not publish port 52334 directly on a public host.

Docker Compose with Caddy

The repository contains deploy/docker-compose.yml and deploy/docker-compose.caddy.yml. Caddy obtains a certificate automatically.

git clone https://github.com/Kaiyuan/lanPrint.git
cd lanPrint/deploy
cp docker-compose.caddy.yml docker-compose.override.yml
# edit the domain and auth code
docker compose -f docker-compose.caddy.yml up -d

One-line install on Linux and macOS

The script installs the bridge binary, generates a server access code, creates a systemd unit (Linux) or launchd daemon (macOS) and starts the service.

# Linux
curl -fsSL https://raw.githubusercontent.com/Kaiyuan/lanPrint/main/scripts/install-bridge.sh | sudo bash

# macOS
curl -fsSL https://raw.githubusercontent.com/Kaiyuan/lanPrint/main/scripts/install-bridge.sh | sudo bash

The access code is printed at the end and stored in /etc/lanprint-bridge/bridge.env (Linux). Keep it secret; it is only used by hosts, not by clients.

systemctl status lanprint-bridge
journalctl -u lanprint-bridge -f

HTTPS with a reverse proxy

The bridge speaks plain HTTP on its listen port and is designed to run behind Caddy, Nginx or Traefik. WebSocket upgrades must be forwarded.

# Caddyfile
bridge.example.com {
    reverse_proxy 127.0.0.1:52334
}
# Nginx
location / {
    proxy_pass http://127.0.0.1:52334;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
}

Set LANPRINT_BRIDGE_PUBLIC_URL=https://bridge.example.com so clients receive the correct URL in their session response.

Connect the desktop app

Host

Settings → Cloud sharing → enable, enter the bridge URL (for example https://bridge.example.com) and the server access code. Save. The 8-character share code appears below.

Client

Connect device → manual → enable cloud connection, enter the bridge URL, the share code and the host access code.

Add printers

The host’s shared printers appear exactly as on a LAN. Add them once; they stay configured and reconnect automatically.

Security notes

  • Use a long random server access code; it is a bearer secret for host registration.
  • Always use HTTPS/WSS in production. Without TLS, metadata and print data cross the network in clear text.
  • Printer access codes are verified by the host, not by the bridge. Argon2id hashes never leave the host.
  • The bridge stores only device identity, share code and timestamps. Print jobs are relayed and not written to disk.
  • Rotate the server code by restarting the bridge with a new value; hosts must re-register.

API reference

All endpoints are JSON over HTTP. Hosts authenticate with the server access code; clients use a short-lived session token issued by /clients/connect.

MethodPathDescription
GET/healthHealth and version.
POST/api/v1/hosts/registerRegister a host and receive a share code (bearer server code).
POST/api/v1/hosts/heartbeatUpdate host presence (bearer host token).
POST/api/v1/clients/connectExchange a share code for a session token and address hint.
GET/ws/hostHost relay WebSocket.
GET/ws/clientClient relay WebSocket.
GET/api/v1/statsHost counts (bearer server code).
Large print jobs are chunked into 256 KiB frames and base64 encoded inside the relay WebSocket. The bridge enforces a bounded in-memory queue and drops stale sessions.

Troubleshooting

  • “Host offline” means the host’s relay WebSocket is not connected. Check the host status bar and its outbound network access.
  • A 401 from /hosts/register means the server access code is wrong.
  • If clients connect but print jobs time out, verify that the reverse proxy forwards WebSocket upgrades and does not buffer responses.
  • The share code changes if /data is not persisted. Mount the volume.
