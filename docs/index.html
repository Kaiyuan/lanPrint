Host and client in one app

Share selected local printers and connect to other hosts from the same window. No separate server install is required.

🖨

Real virtual printers

Added printers appear in the system print dialog. Windows uses a local TCP spool port; Linux and macOS use a CUPS backend.

⌾

Scanning included

All-in-one devices expose their scanner to clients. Windows uses WIA; Linux and macOS use SANE. Results are saved as PNG.

☁

Cloud bridge

Enable cloud sharing on the host, enter the share code on the client, and print from another network through your own bridge server.

🔒

Per-printer access codes

A host-wide code plus optional per-printer codes. Passwords are hashed with Argon2id; clients store signed tokens, never plaintext.

Three steps to share a printer

Install lanPrint on both machines. No IPP, WSD or Samba configuration.

1 · On the host

Open Settings, set a host access code, then toggle the printers you want to share. lanPrint advertises itself over mDNS automatically.

2 · On the client

Click “Connect device”, pick the host from the LAN scan, enter the code, and add the printers you need. They appear in the system print dialog.

3 · Across the internet

Deploy the bridge server, enable cloud sharing on the host, then connect with the generated share code from any network.

Your own print cloud, not someone else's

The bridge is a small Rust service. Run it with Docker or a one-line script on Linux and macOS, put it behind HTTPS, and keep full control of the metadata. Printer data and access codes stay end-to-end between your machines.

Server deployment guide 
# one-line bridge install (Linux)
curl -fsSL https://raw.githubusercontent.com/Kaiyuan/lanPrint/main/scripts/install-bridge.sh | sudo bash

# or Docker
docker run -d --name lanprint-bridge -p 52334:52334 \
  -e LANPRINT_BRIDGE_AUTH_CODE=change-me \
  -v lanprint-data:/data \
  kaiyuan/lanprint-bridge:latest

Compatibility first

Designed for mixed offices, old machines and domestic Linux distributions.

Windows 7+

Native Win32 spooler API, tray icon and a Windows 7 build target. No WebView or browser engine is required.

UOS / Deepin

No GTK/AppIndicator dependency for the tray: Slint uses StatusNotifierItem over D-Bus. Built on a glibc-compatible baseline.

macOS 10.15+

Universal Intel and Apple Silicon builds, CUPS backend and menu-bar integration.
